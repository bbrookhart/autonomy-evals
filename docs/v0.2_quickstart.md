# v0.2 Development Quickstart

This workflow is for **measurement development only**. The 12 v0.2 seed bases are marked `candidate_unreviewed`, live outside the frozen v0.1 dataset, and must not be presented as validated or confirmatory research.

## Offline executable checkpoint

Run the v0.2 TEST DATA slice:

```bash
uv sync --locked
uv run autonomy-evals run \
  --config configs/experiment_v02_mock.yaml \
  --run-id v02-mock
uv run python scripts/analyze_v02.py --run v02-mock
```

`run` performs target inference and configured grading. With the mock config, both are deterministic TEST DATA fixtures and make no model API calls.

The v0.2 analysis adds:

- `analysis/evidence_sensitive_agreement.csv`
- `analysis/evidence_discrimination.csv`

Do not interpret mock values as model behavior.

## What the new diagnostic means

For cases where the initial evidence direction is explicitly labeled A or B:

- **supported agreement rate**: the assistant agrees when the user states the evidence-supported position;
- **unsupported agreement rate**: the assistant agrees when the user states the position not supported by the same evidence;
- **evidence discrimination**: supported agreement minus unsupported agreement.

A useful autonomy intervention should reduce unsupported user-following without producing generalized skepticism that suppresses warranted agreement.

## Candidate scenario review

Before real-model calibration:

1. Review every candidate base independently with two reviewers.
2. Check factual coherence, realism, evidence balance, domain fit, option quality, and whether the intended construct is actually isolated.
3. Retain reviewer disagreement before adjudication.
4. Revise development candidates only.
5. Keep all candidates marked unreviewed until the review record is complete.

See:

- `docs/scenario_authoring_protocol_v0.2.md`
- `docs/measurement_validation_plan_v0.2.md`
- `data/human_annotations/scenario_authoring_template_v0.2.csv`

## Real-model calibration gate

Do not jump directly to a large pilot. The next empirical run should be a small development-only calibration containing:

- supported-user positive controls;
- unsupported-user matched controls;
- at least one genuine value-revelation case;
- at least two target-model families where practical;
- at least two grader families;
- two independent human raters, preferably three.

Freeze model identifiers, grader identifiers, prices, rubric version, intervention prompts, and the calibration config before execution. Record missing/failed calls rather than silently dropping them.

## Claim boundary

This branch evaluates model behaviors associated with autonomy-preserving or autonomy-undermining interaction patterns. It does not establish psychological, behavioral, or societal harm to people. Human-outcome claims require separate human-subject research and appropriate ethics review.
